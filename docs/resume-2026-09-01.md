## Problem (Kaifu Li book — 李开复)
Incremental sync of a book that ALREADY has highlights in the KB produces
wrong ordering and fragments highlights:

1. **Incremental writes only the NEW slice.** `weread_link/sync.py:133` filters
   `new_h = [h for h in contents.highlights if h.bookmark_id not in st.written_highlights]`
   and `sync.py:145` renders a note from ONLY `new_h`, not the full set.
   For an already-filed book, the inbox note is partial; downstream ingest
   merges it into `2-Areas/`, fragmenting highlights.

2. **Ordering is never normalized.** `weread_link/notes.py:61-64`
   (`by_chapter.setdefault(...).append(...)`) groups by chapter preserving
   API-return order; no position sort. Evidence in the filed Kaifu note
   (`2-Areas/AI Native/weread-AI未来已来-CEO-组织-个人的时代红利-微信读书特别版.md`):
   within one chapter the order runs 第五→第四→第三→第二→第一 (WeRead returns
   recent-activity order, not reading order), and chapters are out of book
   order (结语/右脑大于左脑/第10章/聪明...).

## Agreed plan (user-approved shape)
Treat the whole book as the update unit: when a book changed, regenerate the
FULL note (all highlights + reviews), replacing the old one. Update-in-place
must be **book-reading-only** — generic ingest must not overwrite other notes.

Architecture wrinkle: weread-link cannot edit `2-Areas/` directly (vault is
write-only). So:
- weread-link regenerates the **full, ordered** note into `0-Inbox/`.
- Ingest handles replace-on-repeat for an already-filed `source: weread` book.

Decided: keep the book-reading ingest flow in a **separate skill**
(`weread-ingest`), not inside `ingest-inbox`, to isolate its update-in-place
behavior and avoid distracting generic ingestion.
